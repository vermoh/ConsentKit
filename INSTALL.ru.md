# ConsentKit — как поставить баннер cookie на свой сайт

Инструкция для тех, кто не программист. Каждый шаг расписан по кликам. Если какое-то слово непонятно — загляните в [словарик](#словарик) в конце.

---

## Что это и зачем мне это нужно?

Если ваш сайт посещают люди из Европы, закон (GDPR) требует **сначала спросить разрешение**, и только потом включать счётчики посещений, рекламные пиксели и похожие сервисы.

Большинство баннеров «Мы используем cookie» — просто картинка: нажали вы кнопку или нет, счётчики всё равно работают с первой секунды. За это штрафуют.

**ConsentKit — не картинка.** Пока посетитель не нажал «Принять», счётчики на сайте физически не запускаются. Нажал «Отклонить» — не запустятся вообще. Передумал — в любой момент может изменить решение через кнопку «Настройки cookie».

Что увидит посетитель:

1. Внизу страницы появится панель с тремя кнопками: **«Принять всё»**, **«Отклонить всё»**, **«Настроить»**.
2. По кнопке «Настроить» откроется окно, где можно разрешить что-то одно — например, статистику разрешить, а рекламу нет.
3. После выбора панель исчезнет, а в углу останется маленькая круглая кнопка — чтобы передумать.

Баннер сам подстраивается под язык браузера посетителя (34 языка) и под светлую/тёмную тему.

## Вариант А. Сайт на WordPress

### Шаг 1. Подготовьте файл плагина

Найдите в этом проекте папку `plugins/wordpress/consentkit` и упакуйте её в zip-архив:

- **Windows:** правый клик по папке `consentkit` → «Отправить» → «Сжатая ZIP-папка».
- **Mac:** правый клик по папке `consentkit` → «Сжать».

Получится файл `consentkit.zip`.

### Шаг 2. Установите плагин

1. Зайдите в админку своего сайта (обычно это адрес вида `вашсайт.ru/wp-admin`).
2. В меню слева: **Плагины → Добавить новый**.
3. Вверху страницы нажмите кнопку **«Загрузить плагин»**.
4. Нажмите «Выберите файл», укажите ваш `consentkit.zip`, нажмите **«Установить»**.
5. Когда установка закончится — нажмите **«Активировать»**.

### Шаг 3. Настройте

В меню слева: **Настройки → ConsentKit**. Что здесь важно:

- **Категории** — галочки «Аналитика», «Маркетинг», «Функциональные». Оставьте включёнными те, что реально есть на сайте. Стоит только Яндекс Метрика или Google Analytics и нет рекламных пикселей? Оставьте «Аналитику», «Маркетинг» выключите — лишняя категория в баннере только путает посетителя.
- **Язык** — оставьте «auto»: баннер сам определит язык посетителя.
- **Вид** (bar / box / modal) — полоса внизу, компактная карточка в углу или окно по центру. На вкус; «bar» — привычный вариант.
- **Тема** — оставьте «auto» (подстроится под настройки посетителя).
- **Цвет кнопок** — подберите под цвет вашего сайта.
- **Версия политики** — пока не трогайте. Это важно позже: когда вы измените свою политику конфиденциальности, поменяйте здесь «1» на «2» — и баннер спросит согласие у всех заново, как требует закон.
- **Таблица cookie** — список, который посетитель увидит по кнопке «Настроить»: какие cookie есть на сайте и зачем. Заполните честно (см. [подсказку ниже](#что-написать-в-таблице-cookie)).

Нажмите «Сохранить изменения».

### Шаг 4. Добавьте ссылку в подвал сайта

Закон требует, чтобы посетитель мог легко передумать. Маленькая круглая кнопка появится сама, но добавьте ещё и ссылку в подвал (footer) сайта. В любом месте, где WordPress принимает текст (виджет подвала, меню, страница), вставьте:

```
[consentkit_settings]
```

На сайте это превратится в ссылку «Настройки cookie», открывающую окно выбора.

### Шаг 5. Проверьте

Перейдите к разделу [«Как проверить, что всё работает»](#как-проверить-что-всё-работает).

## Вариант Б. Tilda и другие конструкторы

Суть: загрузить на сайт три файла и вставить небольшой код в самое начало «шапки» каждой страницы.

### Шаг 1. Загрузите три файла на сайт

Нужны файлы из папки `src/`:

- `ck-core.js` — «мозг» (следит, чтобы счётчики молчали до согласия)
- `ck-locales.js` — переводы на 32 языка
- `ck-ui.js` — внешний вид баннера

Куда загружать — зависит от конструктора. В Тильде: **Настройки сайта → Ещё → Загрузка файлов** (на бесплатном тарифе может быть недоступно). После загрузки каждый файл получит свой адрес-ссылку — сохраните эти три адреса, они понадобятся в коде ниже.

### Шаг 2. Вставьте код в HEAD

Найдите в конструкторе место для «вставки кода в HEAD». В Тильде: **Настройки сайта → Ещё → HTML-код для вставки внутрь HEAD**.

Вставьте вот это, заменив три адреса на ваши из шага 1:

```html
<script src="АДРЕС-ФАЙЛА-ck-core.js"></script>
<script src="АДРЕС-ФАЙЛА-ck-locales.js"></script>
<script src="АДРЕС-ФАЙЛА-ck-ui.js"></script>
<script>
ConsentKit.init({
  policyVersion: "1",
  language: "auto",
  layout: { type: "bar", position: "bottom" },
  theme:  { accent: "#2B50D8", mode: "auto" },
  cookieTable: [
    { name: "_ym_uid", category: "analytics", vendor: "Яндекс",
      purpose: "Статистика посещений", expiry: "1 год" }
  ]
});
</script>
```

Два правила, от которых зависит законность:

1. **Этот код должен стоять ПЕРВЫМ** — выше кода Метрики, Analytics, пикселей и любых других вставок. Если счётчик стоит выше — он успеет сработать до баннера.
2. **Ничего не переставляйте внутри** — порядок трёх файлов важен.

Что можно менять безопасно:

- `accent: "#2B50D8"` — цвет кнопок (вставьте свой код цвета, его можно взять в настройках стиля вашего сайта);
- `type: "bar"` — вид баннера: `"bar"` (полоса), `"box"` (карточка в углу), `"modal"` (окно по центру);
- список `cookieTable` — [что здесь писать](#что-написать-в-таблице-cookie).

### Шаг 3. Про ваши счётчики

Хорошая новость: **самые популярные счётчики размечать не нужно.** Яндекс Метрику, Google Analytics, пиксель Meta*, Hotjar, TikTok и другие известные сервисы ConsentKit узнаёт и придерживает сам.

Если на сайте есть что-то экзотическое (виджет чата, нестандартный счётчик) — попросите того, кто его вставлял, разметить код по инструкции для разработчиков ([README.md](README.md), раздел про `text/plain`). Или пришлите нам — подскажем.

Видео YouTube и карты, вставленные кодом (iframe), тоже требуют разметки — это работа на пару минут для любого, кто умеет редактировать HTML.

### Шаг 4. Ссылка в подвале

Добавьте в подвал сайта ссылку «Настройки cookie». В Тильде это блок футера; если конструктор позволяет вставить HTML, используйте:

```html
<a href="#" onclick="ConsentKit.show(); return false">Настройки cookie</a>
```

Если HTML вставить нельзя — не страшно: круглая кнопка в углу экрана появляется автоматически и выполняет ту же роль.

### Шаг 5. Проверьте

Раздел [«Как проверить, что всё работает»](#как-проверить-что-всё-работает).

## Вариант В. У вас есть разработчик

Отправьте разработчику эту папку целиком и одну фразу:

> «Поставь ConsentKit по README.md: три скрипта из `src/` первыми в `<head>`, инициализация `ConsentKit.init`, наши счётчики — через автоблок или разметку `data-ck`. Для React есть пакет в `npm/`. Проверка — по чеклисту в конце INSTALL.ru.md».

Всё остальное он поймёт из [README.md](README.md) (английский, для разработчиков) и [SPEC.md](SPEC.md) (полное описание архитектуры). Вопросы, которые стоит задать разработчику по завершении:

1. «Покажи, что до нажатия кнопки счётчики молчат» — пусть продемонстрирует (это главный смысл всей затеи).
2. «Ссылка "Настройки cookie" есть в подвале?»
3. «Таблица cookie в баннере заполнена нашими реальными сервисами?»

## Что написать в таблице cookie

Таблица — это то, что посетитель увидит, нажав «Настроить». По одной строчке на каждый сервис. Примеры готовых строчек — берите и меняйте:

**Яндекс Метрика:**
```json
{ "name": "_ym_uid", "category": "analytics", "vendor": "Яндекс",
  "purpose": "Статистика посещений сайта", "expiry": "1 год" }
```

**Google Analytics:**
```json
{ "name": "_ga", "category": "analytics", "vendor": "Google",
  "purpose": "Статистика посещений сайта", "expiry": "2 года" }
```

**Пиксель Meta* (Facebook):**
```json
{ "name": "_fbp", "category": "marketing", "vendor": "Meta",
  "purpose": "Показ рекламы тем, кто был на сайте", "expiry": "3 месяца" }
```

Несколько строчек разделяются запятой. В плагине WordPress всё это вставляется в поле «Таблица cookie» в квадратных скобках:

```json
[
  { "name": "_ym_uid", "category": "analytics", "vendor": "Яндекс",
    "purpose": "Статистика посещений сайта", "expiry": "1 год" },
  { "name": "_ga", "category": "analytics", "vendor": "Google",
    "purpose": "Статистика посещений сайта", "expiry": "2 года" }
]
```

Если при сохранении плагин ругается «неверный формат» — чаще всего потеряна запятая между строчками или кавычка. Ничего не сломается: старое значение сохранится, просто поправьте и сохраните ещё раз.

Не знаете, какие сервисы стоят на вашем сайте? Простой способ: откройте сайт в Chrome, нажмите на замочек слева от адреса → «Файлы cookie и данные сайтов» — увидите список имён. Имена, начинающиеся с `_ym` — Метрика, `_ga` — Google Analytics, `_fb` — Meta.

## Как проверить, что всё работает

Проверка занимает пять минут и не требует специальных программ.

**1. Баннер появляется.**
Откройте свой сайт в режиме инкогнито (Chrome: меню → «Новое окно в режиме инкогнито», или Ctrl+Shift+N / Cmd+Shift+N). Инкогнито нужен, чтобы браузер «забыл», что вы уже нажимали кнопки. Баннер должен появиться сразу.

**2. Все три кнопки на месте.**
«Принять всё», «Отклонить всё», «Настроить» — одинакового размера. «Отклонить» не спрятана и не серая — так и задумано, это требование закона, и убрать её в ConsentKit нельзя.

**3. До нажатия — счётчики молчат.**
Не нажимая ничего на баннере, посмотрите на замочек слева от адреса → «Файлы cookie». Там НЕ должно быть `_ym_uid`, `_ga`, `_fbp` и подобных. Если есть — какой-то счётчик стоит в коде выше ConsentKit; передвиньте код ConsentKit выше (Вариант Б, шаг 2) или напишите разработчику.

**4. После «Принять» — работают.**
Нажмите «Принять всё», обновите страницу, посмотрите cookie снова — теперь `_ym_uid` / `_ga` должны появиться. И проверьте свою Метрику/Analytics: визит засчитался.

**5. Выбор запоминается.**
Обновите страницу — баннер не должен появиться снова (в том же окне).

**6. Передумать можно.**
Найдите круглую кнопку в углу (или ссылку в подвале), откройте настройки, нажмите «Отклонить всё». Проверьте cookie — счётчиковые должны исчезнуть.

Все шесть пунктов сошлись? Готово, сайт спрашивает согласие по-настоящему.

## Если вы пользуетесь Google Tag Manager

Если счётчики на сайте подключены не напрямую, а через Google Tag Manager, для вас есть готовый набор: файл `integrations/gtm/container-import.json` импортируется в GTM и создаёт «триггеры» — правила вида «запускать этот тег только после согласия на аналитику».

Импорт делается в GTM: **Администрирование → Импорт контейнера**, режим **«Слияние» (Merge)**. Дальше свои теги нужно привязать к появившимся триггерам — это лучше поручить тому, кто настраивал вам GTM, вместе с подробной инструкцией [integrations/gtm/README.md](integrations/gtm/README.md).

Важно: код ConsentKit на сайте должен стоять **выше** кода GTM.

## Частые вопросы

**Посетитель нажал «Отклонить». Я теряю статистику?**
По этому посетителю — да, так работает закон: нет согласия — нет счётчика. Практика показывает, что честный баннер с понятными формулировками собирает больше согласий, чем агрессивный.

**Я изменил политику конфиденциальности. Что делать?**
Поменяйте «Версию политики» (в плагине — поле в настройках; в коде — `policyVersion: "1"` на `"2"`). Баннер спросит согласие у всех заново.

**Хочу баннер на английском для всех, без автоопределения.**
В плагине выберите язык в настройках. В коде замените `language: "auto"` на `language: "en"`.

**Как понять, что нажимают посетители?**
В прототипе статистики нажатий нет — она появится в следующей версии вместе с личным кабинетом. Сам факт выбора каждого посетителя сохраняется у него в браузере (cookie `ck_consent`).

**Баннер не появился.**
Проверяйте в инкогнито (см. проверку №1 — браузер помнит ваш прошлый выбор). Если и в инкогнито нет — код вставлен не в HEAD или адреса файлов указаны с ошибкой.

**Это на 100% делает сайт законным?**
Технически — да, счётчики без согласия работать не будут. Но GDPR это ещё и тексты: политика конфиденциальности, список сервисов, правовые основания. Их стоит проверить с юристом. И учтите: это прототип — переводы баннера на редкие языки пока черновые.

## Словарик

- **Cookie (куки)** — маленькие записи, которые сайт оставляет в браузере посетителя. Бывают необходимые (корзина магазина, вход в аккаунт) и следящие (счётчики, реклама). Спрашивать разрешение нужно только на вторые.
- **GDPR** — европейский закон о персональных данных. Действует, если сайт посещают жители ЕС, — неважно, где находитесь вы.
- **HEAD (шапка страницы)** — невидимая служебная часть страницы, куда вставляют коды счётчиков и баннеров. У конструкторов для этого есть специальное поле в настройках.
- **Счётчик / трекер / пиксель** — код сторонней компании на вашем сайте, который собирает данные о посетителях: Яндекс Метрика, Google Analytics, пиксель Meta и т. п.
- **Категории согласия** — группы, на которые посетитель даёт отдельные разрешения: «Аналитика» (статистика), «Маркетинг» (реклама), «Функциональные» (удобства вроде чата). «Необходимые» разрешения не требуют — без них сайт не работает.
- **Плагин** — дополнение для WordPress, устанавливается из админки в пару кликов.
- **Google Tag Manager (GTM)** — «диспетчер», через который на сайт подключают счётчики. Если не знаете, есть ли он у вас, — скорее всего, нет.
